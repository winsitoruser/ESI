# Humanify SaaS Security & Defense Master Checklist

> **Tujuan:** menjadi baseline keamanan untuk bisnis SaaS/HR SaaS agar lebih tahan terhadap hacking, cracking, phishing, credential theft, bot abuse, fraud/cheating, data theft, ransomware, DDoS, insider threat, supply-chain attack, dan kesalahan konfigurasi.
>
> **Catatan:** keamanan bukan satu fitur. Pertahanan yang baik menggunakan **defense in depth**: governance + identity + application + infrastructure + data + monitoring + people + incident response.

## 1. Prioritas

| Level | Arti | Target |
|---|---|---|
| **P0** | Critical / wajib sebelum production atau secepatnya | 0–30 hari |
| **P1** | High priority | 30–60 hari |
| **P2** | Medium / maturity | 60–90 hari |
| **P3** | Advanced / continuous improvement | 90+ hari |

## 2. Framework Acuan

Gunakan checklist ini bersama dengan:

- **NIST Cybersecurity Framework (CSF) 2.0** — Govern, Identify, Protect, Detect, Respond, Recover.
- **CIS Critical Security Controls v8.1** — baseline kontrol keamanan terprioritas.
- **OWASP Top 10:2025** — risiko utama web application.
- **OWASP ASVS 5.0** — requirement dan verification standard untuk aplikasi.
- **OWASP API Security Top 10:2023** — keamanan API.
- **NIST Secure Software Development Framework / SSDF** — secure SDLC.
- **UU No. 27 Tahun 2022 tentang Pelindungan Data Pribadi** — untuk pemrosesan data pribadi di Indonesia.
- Pertimbangkan **ISO/IEC 27001** dan **SOC 2** saat bisnis memasuki enterprise market.

# B. IDENTITY, LOGIN & ACCOUNT SECURITY

### Ancaman
Phishing, credential stuffing, brute-force, password spraying, session theft, account takeover.

- [ ] **SEC-IAM-001 — P0 — Wajib MFA untuk seluruh internal admin**
  - Utamakan passkey / FIDO2 / WebAuthn.
  - Hindari SMS sebagai metode utama untuk privileged account.

- [ ] **SEC-IAM-002 — P0 — MFA untuk customer administrator**
  - Minimal optional saat awal.
  - Target menjadi mandatory untuk super-admin tenant.

- [ ] **SEC-IAM-003 — P0 — Password disimpan dengan password hashing yang sesuai**
  - Jangan plaintext.
  - Jangan reversible encryption untuk password.

- [ ] **SEC-IAM-004 — P0 — Rate limit login**
  - Per account.
  - Per IP/network.
  - Adaptive/risk-based throttling.

- [ ] **SEC-IAM-005 — P0 — Proteksi credential stuffing**
  - Rate limiting.
  - Bot signal.
  - Failed login anomaly.
  - Known compromised password detection bila tersedia.

- [ ] **SEC-IAM-006 — P0 — Secure password reset**
  - Short-lived single-use token.
  - Token tidak disimpan plaintext.
  - Jangan mengungkap apakah email terdaftar.
  - Invalidate/reset relevant sessions setelah reset jika perlu.

- [ ] **SEC-IAM-007 — P0 — Secure session management**
  - HttpOnly.
  - Secure.
  - SameSite.
  - Session expiration.
  - Session rotation setelah login/privilege change.

- [ ] **SEC-IAM-008 — P0 — Re-authentication untuk aksi sensitif**
  - Ganti email.
  - Ganti password.
  - Add admin.
  - Export mass data.
  - Change bank/payroll config.
  - Disable MFA.

- [ ] **SEC-IAM-009 — P0 — RBAC / Role-Based Access Control**
  - User.
  - HR.
  - Manager.
  - Finance.
  - Tenant Admin.
  - Humanify Support.
  - Super Admin.

- [ ] **SEC-IAM-010 — P0 — Default-deny authorization**
  - User hanya dapat resource yang secara eksplisit diizinkan.

- [ ] **SEC-IAM-011 — P0 — Least privilege**
  - Internal engineer/support tidak otomatis mendapat production access.

- [ ] **SEC-IAM-012 — P0 — Separate privileged/admin account**
  - Jangan gunakan akun admin untuk pekerjaan sehari-hari.

- [ ] **SEC-IAM-013 — P1 — Login notification**
  - New device.
  - New country.
  - Password changed.
  - MFA changed.

- [ ] **SEC-IAM-014 — P1 — Active session/device management**
  - User dapat melihat dan revoke session.

- [ ] **SEC-IAM-015 — P1 — SSO/SAML/OIDC untuk enterprise tenant**

- [ ] **SEC-IAM-016 — P1 — SCIM/JIT provisioning untuk enterprise**
  - Mempercepat offboarding employee.

- [ ] **SEC-IAM-017 — P1 — Break-glass admin account**
  - Sangat terbatas.
  - Hardware MFA.
  - Usage alert.
  - Credential disimpan aman.

- [ ] **SEC-IAM-018 — P2 — Risk-based authentication**
  - Impossible travel.
  - New device.
  - Abnormal IP.
  - Suspicious automation.
  - Privileged action anomaly.

- [ ] **SEC-APP-010 — P0 — SSRF protection**

- [ ] **SEC-APP-014 — P1 — Business logic abuse testing**

  - Duplicate transaction.
  - Replay.
  - Negative/abnormal values.
  - Sequence manipulation.

- [ ] **SEC-APP-015 — P1 — Validate redirect URL untuk mencegah open redirect/phishing**

- [ ] **SEC-APP-016 — P1 — Protect sensitive download links**

# Security Philosophy

1. **Zero Trust:** jangan mempercayai request hanya karena datang dari network/internal service.
2. **Least Privilege:** setiap user/service mendapat hak minimum.
3. **Default Deny:** akses ditolak kecuali secara eksplisit diizinkan.
4. **Defense in Depth:** jangan mengandalkan satu kontrol.
5. **Assume Breach:** desain seolah satu credential atau komponen suatu hari dapat bocor.
6. **Secure by Default:** konfigurasi default harus aman.
7. **Privacy by Design:** minimalkan dan lindungi data sejak tahap desain.
8. **Auditability:** aksi sensitif harus bisa ditelusuri.
9. **Fail Securely:** ketika error, sistem tidak membuka akses.
10. **Continuous Security:** security adalah proses berulang, bukan checklist satu kali.

# Definition of Done untuk Security Task

Sebuah security task belum dianggap selesai hanya karena fitur sudah dibuat. Minimal harus memenuhi:

- [ ] Requirement terdokumentasi.
- [ ] Code/config reviewed.
- [ ] Test dibuat.
- [ ] Negative/abuse case diuji.
- [ ] Logging tersedia bila relevan.
